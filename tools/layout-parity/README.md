# בדיקת עימוד מתמטית־מוחלטת מול הגרסה הישנה (Layout Parity)

> "ותמצא את הדרכים לבדיקה של העימוד בצורה מתמטית ומוחלטת, שתבהיר האם
> התיקון הזה והתיקונים שיהיו בעקבותיו עזרו, ושאפשר להריץ אותה דרך
> וורקפלו של גיטהאב." — בקשת המשתמש, 03.11

המערכת משווה את העימוד של RED מול **האמת של התוכנה הישנה** — קובצי ה‑PDF
שהועלו ל־`audits/` (הפלט המלא של הגרסה הצהובה על `no_long_test_text.txt`),
כולל שלוש גרסאות עם **סימון גיאומטרי בלתי־נראה** (טקסט לבן ב‑Consolas שהמנוע
הישן מטמיע בעימוד עצמו).

## איך עובד הקסם — פענוח הסימון הגיאומטרי

הגרסה הישנה סימנה את המבנה שלה בטקסט לבן (נראה למחלץ, בלתי נראה לעין):

| תגית | משמעות |
|---|---|
| `page N` | תיבת עמוד |
| `wrapper header` / `page-number` | אזור הכותרת העליונה / העמודון |
| `body-flow 680×915` | זרימת הגוף (רוחב×גובה בפיקסלים של המקור) |
| `block-2col 680×336` / `block-single-col` / `block-h3-span` | סוג בלוק ומידותיו |
| `col:right 269×336 \| 5p 41l 281w` | טור ימני: 269px רוחב, 5 פסקאות, 41 שורות, 281 מילים |
| `p-end 11l 72w "והנה המעשה…"` | סוף פסקה: 11 שורות, 72 מילים, מילים פותחות |
| `p-cut 6l 43w "…"` | פסקה נחתכה בתחתית העמוד/טור (ממשיכה בעמוד הבא) |
| `h2-title 1l "…"` / `h2-siman` / `h4 1l` | כותרות עם מספר שורות |
| `margin-col` / `side-note` / `fn-num` / `note-marker` | טור שוליים, הערת צד, סמן הערה |

בנוסף, כל שורת טקסט מסומנת במספר — **רוחבה בפיקסלים** (`269` = שורה מיושרת
מלאה). כלומר: לכל פסקה בספר קיים בייחוס מספר השורות והמילים המדויק, ולכל
שורה — הגיאומטריה המדויקת. זו האמת המתמטית המלאה של העימוד המקורי.

## הרכיבים

```
tools/layout-parity/
  extract-reference.py   →  audits/layout-reference.json   (מחויב במאגר; דטרמיניסטי)
  run-ours.js            →  ours-model.json + ours.pdf     (הנתיב החי של RED)
  compare.py             →  parity-report.json + קוד יציאה
.github/workflows/layout-parity.yml                        (הרצה בכל push)
```

**נתיב ההרצה שלנו זהה לעליית האפליקציה**: ברירות המחדל המקוריות
(`default_settings.json` → `importImudSettings`), מדידה בגופן האמיתי של הגוף
(`Guttman-Rashi-Normal.ttf` דרך `registerFont` + `measure-impl: font-metrics`),
והן את המודל והן את ה‑PDF מיוצאים מאותן הגדרות בדיוק.

## הבדיקות

**HARD — אינווריאנטים מוחלטים** (נכונות בפני עצמה):

| קוד | בדיקה |
|---|---|
| H1 | שימור תוכן — מולטיסט המילים בפלט זהה למקור |
| H2 | אפס חפיפות שורות ב‑PDF (טקסט אחד על השני) |
| H3 | כל הטקסט בתוך גבולות העמוד |
| H4 | שורות גוף מגיעות לשתי שפות הטור (יישור) |

**PARITY — זהות למקור** (כל תיקוץ אמור לקרב):

| קוד | בדיקה | הייחוס |
|---|---|---|
| P1 | מספר עמודים | 54 |
| P2 | רצף סוגי עמודים | שער ראשי→אחורי→תוכן×3→ריק→שער משנה→תוכן מפורט×3→פתיחה→גוף×43 |
| P3a | פורמט עמודון | גימטריה יחידה בלי גרשיים (`ב`, לא `ב׳`) |
| P3b | רצף ערכי עמודונים | 50 עמודונים, מ־`א` ואילך, מתחיל בעמוד תוכן־העניינים הראשון |
| P4 | כותרות עליונות | ימין=`מקום` (מילה ראשונה של שם הספר **מהמסמך**), מרכז=פרק נוכחי, שמאל=`בינה` |
| P5 | תוכן־עניינים כפול | כללי (3 עמודים, ~72 ערכים) + מפורט (3 עמודים, ~90 ערכים) |
| P6 | רצף פסקאות | 278 פסקאות, 3,149 שורות, 21,861 מילים — כולל פיצול מניית המקור (א. ב. ג.) |
| P7 | שקילות שבירת שורות | טקסט כל שורה בסדר קריאה |
| P8a | תיבות טורים | ימין [302.7, 504.8]pt, שמאל [90.5, 292.6]pt (269px) |
| P8b | פס כותרת עליונה | y=42.6–57.6pt |
| P8c | מיקום עמודון | מרכז תחתון, x≈297.6, y≈783.8 |
| P8d | גופן וגודל גוף | Guttman Rashi @ 12pt |
| P8e | פס שורות | 16.08pt (12 × 1.34) |
| P9 | כותרות פתיחה קומפקטיות | בלי מתיחת מילים על רוחב העמוד |

קודי יציאה: `0` הכל עובר | `1` כשל HARD | `2` כשל PARITY | `3` שניהם.
הציון (אחוז בדיקות שעוברות) הוא מד ההתקדמות — **עלה = התיקון עזר, ירד = נסיגה**.

## מצב נוכחי (תיעוד כנות — נעול בזמן ההקמה)

הרצה ראשונה: **ציון 16.7%** (HARD ‏1/4, PARITY ‏2/14). ממצאים מרכזיים
שהמערכת הוכיחה מהקוד בלבד:

1. **הטור השמאלי נשפך מחוץ לעמוד** — x‏=‎−3.7 עד 242 במקום [90.5, 292.6];
   הטורים אצלנו ברוחב ~242pt במקום 202pt (עמודי הגוף כמעט ברוחב מלא, בלי
   טור השוליים של המקור).
2. **מזהים גולמיים דולפים לטקסט** — השורה `כותרת 0 מספר 1 - הקדמה` מופיעה
   כטקסט ספר בעמוד פתיחת הפרק.
3. **כותרות עליונות שגויות** — `ספר מלכי המלוכה` (placeholder מההגדרות) במקום
   שם הספר מהמסמך (`מקום בינה`) מפוצל לשני סלוטים + שם פרק במרכז; והן יושבות
   ב־y≈21 במקום פס 42.6–57.6.
4. **תוכן־עניינים כמעט ריק** — 4 ערכים כלליים במקום ~72, ואפס מפורט במקום ~90
   (המפורט כבוי אצלנו ומופעל במקור).
5. **עמודונים** — `ב׳` עם גרשיים במקום `ב` חד־אותיות; מתחילים בעמוד הלא־נכון.
6. **כותרת פתיחת פרק נמתחת** על רוחב העמוד עם פערי מילים של עד 285pt.
7. **עמוד השער־משנה ריק** — הכותרת שלו דולפת לעמוד פתיחת הפרק במקום להיות
   עמוד שער עצמאי אחרי התוכן־עניינים (+עמוד ריק חסר).
8. **פיצול מניית המקור** (א. ב. ג. בתוך פסקה → פסקאות נפרדות) לא מיושם אצלנו.
9. שבירת שורות שונה (יחס 0.12) — הגיאומטריה השונה של הטורים משנה את כל שבירת
   השורות; המדידה בגופן האמיתי כבר נותנת 57 עמודים מול 54 (פער 5.6% בצפיפות).

הצעד הבא הטבעי: לתקן לפי הסדר — גיאומטריית הטורים (P8a) קודם, כי היא השורש
של P6/P7/P1; אחר כך כותרות/עמודונים/תוכן־עניינים; ואז פיצול המנייה ושבירת
השורות. כל תיקון — והציון אמור לעלות, והוורקפלו מוכיח זאת בכל push.

## אימות אינווריאנטים מוחלטים על הקורפוס הגדול (04.11)

> "וכל הבדיקות צריכות להיעשות על הקובץ ה'גדול מאוד'" — בקשת המשתמש, 04.11

`verify-corpus.py` מאמת את הפלט על **כל קורפוס** באינווריאנטים מוחלטים — תכונות
שכל עימוד נכון חייב לקיים בפני עצמו, בלי תלות בייחוס של הגרסה הישנה (שקיים רק
ל-no_long):

| קוד | בדיקה |
|---|---|
| C1 | שימור תוכן — מולטיסט מילים (גוף+מרזב) זהה למקור; הערה המופיעה במקור פעמיים מילולית נספרת פעם אחת |
| C2 | אפס חפיפות שורות ב-PDF |
| C3 | כל הטקסט בתוך גבולות העמוד |
| C4 | יישור — שיעור הגעה לשתי שפות הטור (רצפה 60%; המקור עצמו מגיע ל-69.1%) |
| C5 | רצף עמודונים — מונה עוקב (כולל נסתרים: ריק ושער-משנה צורכים מספר), גימטריה תקנית (טו/טז) |
| C6 | מכונת מצבים — שערים → תוכן-כללי → [ריק] → שער-משנה → תוכן-מפורט → גוף; מספר השערים-המשנה == h1, פתיחות-הפרק == h0 |
| C7 | שלמות תוכן-עניינים — רצף הערכים תואם למקור, וכל עמודון מצביע על העמוד שבו הכותרת מופיעה בפועל (h1 → שער נסתר, כמקור) |
| C8 | כותרות עליונות — חצאי שם הספר מהמסמך בצדדים; מרכז = כותרת h0/h2 אמיתית (או כותרת ה-TOC בעמודי ה-TOC) |
| C9 | שימור כותרות — כל כותרת h0..h6 מהמקור מופיעה בפלט |
| C10 | הערות שוליים — אפס כפילויות בתוך עמוד; סמנים עוקבים מ-א' בכל עמוד (הוכח מהייחוס: כל אזורי ההערות של המקור פותחים ב-א'); כל הערה היא הערת [..] אמיתית וכל הערת מקור מופיעה |
| C11 | PDF תקין — מספר עמודים תואם למודל, כל הגופנים מוטמעים |
| C12 | ייצוא HTML (S4.11) — מספר עמודים תואם למודל; כותרת עליונה לכל עמוד תוכן; rtl; אין NaN/undefined — אותו dom-renderer כמו התצוגה החיה |

הדטרמיניזם נבדק בנפרד: `run-ours.js --determinism` מריץ את העימוד פעמיים
ונכשל אם ה-hash או מספר העמודים שונים.

```bash
node tools/layout-parity/run-ours.js audits/very_long_test_text.txt audits/very-long-artifacts --determinism --html
python3 tools/layout-parity/verify-corpus.py audits/very_long_test_text.txt \
  audits/very-long-artifacts/ours-model.json audits/very-long-artifacts/ours.pdf \
  audits/very-long-artifacts/corpus-report.json audits/very-long-artifacts/ours.html
```

**מצב נוכחי (04.11, S4.11):** very_long — **12/12 (100%)** כולל ייצוא HTML
(16.3MB על 735 עמודים); no_long — 12/12 (100%); קבלה מול הייחוס (no_long
בלבד) — 72.2% (HARD 4/4, PARITY 9/14; השאר כיול צפיפות עדין — P1/P3b/P4/P6/P7);
אודיט דפדפן אמיתי על very_long — 849/849 עמודים, 53,574 שורות, **אפס בעיות**
(סריקת-גלילה מודעת-וירטואליזציה — ראה tools/layout-audit/).

### מה הקורפוס הגדול חשף (ותוקן — S4.10)
1. **כפילות הערות בתוך עמוד** — שלושה מסלולי דחיפה לתור ההערות, שניים מהם בלי
   דה-דופ: הערה של פסקה שנפתחה ומוקמה באותו עמוד הופיעה פעמיים (70 עמודים
   ב-very_long). אוחדו ל-enqueueNote אחד עם מספור עמודי עוקב מ-א'.
2. **מיזוג הערות סמוכות** — הדבקת '\s+[' יצרה מילה כמו 'אותו[n1][n2]', והחילוץ
   לקח מ-[ הראשון עד-] האחרון: שתי הערות התמזגו לאחת ענקית (1,288 מילים).
   כעת findNotes מפצל את כל ההערות שבמילה (כמו findDelimiterMatches במקור).
3. **בליעת הערה לתוך הערת-צד + דריסה** — ההדבקה חצתה שורות גם לתוך כותרות:
   הערה שבאה אחרי 'כותרת 7' נבלעה להערת-הצד, והערת-צד נוספת שאחריה דרסה
   אותה סופית — 3 הערות וכותרות-צד אבדו לחלוטין (1,353 מילים). כעת ההדבקה
   פועלת לפסקה הקודמת בלבד, והערות-צד מצטברות במקום להידרס.

כל שלושת התיקונים הוכחו כנכונים גם על הייחוס: הציון נשמר (72.2%) וכל
389 הבדיקות ירוקות.
