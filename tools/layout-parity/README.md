# השוואה היסטורית לדוגמת עימוד מוקדמת — Layout Comparison (Diagnostic Only)

> **הבהרה מחייבת (10.11.2026):** קובצי ה-PDF הישנים שב-`audits/` הועלו בשלב מוקדם כדי להמחיש את הכיוון הכללי — יחסי אזורי העמוד, חלוקת הטורים, סוגי העימוד והשערים. הם אינם תוצאה סופית רצויה, אינם חפים מטעויות ואינם מפרט עימוד. אין לחקות מהם את הטקסט, מספרי הפסקאות, שבירת השורות, מספרי העמודים או המידות המדויקות.

כלי זה משווה את RED לדוגמת עימוד היסטורית של Yellow על `no_long_test_text.txt`. הוא שימושי לאיתור הבדלים ולחקירת התפתחות המנוע, אך תוצאתו היא **מרחק מדוגמה מוקדמת**, לא ציון נכונות ולא ציון איכות של RED. פער מן הדוגמה אינו באג עד שהוכח שהוא מפר דרישת משתמש או אינווריאנט הנדסי. שיפור המוצר עשוי להקטין או להגדיל את המרחק מן הדוגמה.

היררכיית הסמכות: הוראות משתמש מפורשות ועדכניות → דרישות מוצר תקפות → אינווריאנטים הנדסיים → העדפות/מידות שאושרו במפורש → קובצי ה-PDF הישנים (חומר עזר לא-נורמטיבי). ראו `spec/REFERENCE_AND_ACCEPTANCE_POLICY.md`.

## מה הכלי עושה

ה-PDFs הישנים כוללים שכבת טקסט וסימונים גיאומטריים בלתי-נראים. `extract-reference.py` מפענח אותם ל-`audits/layout-reference.json`; `run-ours.js` מפיק מודל ו-PDF מ-RED; `compare.py` מפיק דוח P1–P9. החילוץ יכול להיות דטרמיניסטי בלי שה-PDF עצמו יהיה מפרט נכון או סופי.

התגיות ההיסטוריות (page, body-flow, block-2col, col:right/left, p-end/p-cut, h2 וכו') הן תיאור של מה שהופיע בקובץ הישן, לא הוראות למנוע החדש.

## סוגי בדיקות — לא לערבב בין סמכותן

### אינווריאנטים עצמאיים (HARD)

| קוד | בדיקה | מעמד |
|---|---|---|
| H1 | שימור תוכן מול מקור הקלט | אינווריאנט מחייב |
| H2 | היעדר חפיפות אסורות | אינווריאנט מחייב, לפי חריגים מוגדרים |
| H3 | הטקסט בתוך גבולות העמוד/אזורו המותר | אינווריאנט מחייב, לפי תבניות וחריגים |

### מדד איכות — יישור (H4)

H4 מודד את שיעור השורות המגיעות לשתי שפות הטור. ב-compare.py המדידה ההיסטורית נגזרת מה-PDF הישן ולכן היא LEGACY בלבד; ב-verify-corpus.py היא מידעית כברירת מחדל. אין רצפת יישור מחייבת ללא אישור מפורש של המשתמש.

### השוואה לדוגמה ההיסטורית (P1–P9)

כל הפריטים הבאים מתארים הבדל לעומת הקובץ הישן בלבד. ערכיהם אינם יעדי קבלה:

| קוד | מה מושווה | שימוש מותר |
|---|---|---|
| P1 | מספר עמודים | איתור הבדל בהיקף |
| P2 | רצף סוגי עמודים | הבנת מבנה היסטורי |
| P3a/P3b | פורמט ורצף עמודונים | בדיקת התנהגות לעומת הדוגמה |
| P4 | כותרות עליונות | איתור הבדל בסלוטים |
| P5 | תוכן-עניינים | איתור הבדל במבנה/כמות |
| P6 | רצף פסקאות, ראשים, שורות ומילים | חקירת טוקניזציה/חילוץ/גבולות פסקה |
| P7 | רצף שורות לאחר נרמול | חקירת הבדלים בשבירת שורות |
| P8a–P8e | גאומטריה, כותרת, עמודון, גופן ופס שורות | נקודות מדידה היסטוריות בלבד |
| P9 | קומפקטיות כותרות פתיחה | תצפית על דוגמת העימוד |

**P6/P7 אינם שערי נכונות.** הם מושפעים גם מזהות קובץ המקור ומארטיפקטים של חילוץ ה-PDF. לפני פירוש פער יש לוודא אותו קלט, גרסה, הגדרות ונרמול. יש לסווג פער כפער מקור/גרסה, ארטיפקט חילוץ, הבדל מכוון, הפרת דרישת משתמש או באג מוכח. רק האחרון מצדיק תיקון מנוע.

אין להשתמש בציון P1–P9 כ-ratchet, כרצפת CI או כמדד "איכות המנוע". אין להעלות ציון באמצעות פשרה שמזיקה לתוצאה הרצויה; ואין לפסול שיפור רק מפני שהציון ההיסטורי ירד.

## הרצה

```bash
python3 tools/layout-parity/extract-reference.py
node tools/layout-parity/run-ours.js
python3 tools/layout-parity/compare.py
```

החילוץ הדטרמיניסטי מאמת שה-JSON מתאים ל-PDF ההיסטורי שממנו נוצר; הוא אינו מאמת שה-PDF הוא מפרט המוצר.

ה-workflow ממשיך להריץ את ההשוואה ולהעלות artifacts לצורך אבחון. רק אינווריאנטים עצמאיים ובדיקות דרישות מאושרות משמשים שערי נכונות. היעדר התאמה ל-PDF הישן מדווח כ-`legacy sample distance` ולא ככישלון איכות.

## קריאת תוצאות היסטוריות

ציונים, ספירות P6/P7, מספרי עמודים ונתוני שורות שתועדו בסעיפים ההיסטוריים של README זה נשארים לצורך מעקב אחר התפתחות הכלי. אין לפרשם כמצב קבלה נוכחי, כיעד סופי או כהוכחה לאיכות. בכל דוח חדש יש לציין commit, קלט, הגדרות, run ו-artifact, ולצרף סיווג לפערים.

7. **עמוד השער־משנה ריק** — הכותרת שלו דולפת לעמוד פתיחת הפרק במקום להיות

## אימות אינווריאנטים מוחלטים על הקורפוס הגדול (04.11)

> "וכל הבדיקות צריכות להיעשות על הקובץ ה'גדול מאוד'" — בקשת המשתמש, 04.11

`verify-corpus.py` מאמת את הפלט על **כל קורפוס**. C1–C3 ו-C5–C12 בודקים
אינווריאנטים/חוזים פנימיים לפי הגדרתם; C4 הוא מדד איכות יישור בלבד ומדווח
כמידע כברירת מחדל, ללא סף שנגזר מה-PDF הישן:

| קוד | בדיקה |
|---|---|
| C1 | שימור תוכן — מולטיסט מילים (גוף+מרזב) זהה למקור; הערה המופיעה במקור פעמיים מילולית נספרת פעם אחת |
| C2 | אפס חפיפות שורות ב-PDF |
| C3 | כל הטקסט בתוך גבולות העמוד |
| C4 | מדד איכות יישור — שיעור הגעה לשתי שפות הטור | מידע בלבד כברירת מחדל; סף מחייב רק אם אושר ומועבר במפורש |
| C5 | רצף עמודונים — מונה עוקב (כולל נסתרים: ריק ושער-משנה צורכים מספר), גימטריה תקנית (טו/טז) |
| C6 | מכונת מצבים — שערים → תוכן-כללי → [ריק] → שער-משנה → תוכן-מפורט → גוף; מספר השערים-המשנה == h1, פתיחות-הפרק == h0 |
| C7 | שלמות תוכן-עניינים — רצף הערכים תואם למקור, וכל עמודון מצביע על העמוד שבו הכותרת מופיעה בפועל (h1 → שער נסתר, כמקור) |
| C8 | כותרות עליונות — חצאי שם הספר מהמסמך בצדדים; מרכז = כותרת h0/h2 אמיתית (או כותרת ה-TOC בעמודי ה-TOC) |
| C9 | שימור כותרות — כל כותרת h0..h6 מהמקור מופיעה בפלט |
| C10 | הערות שוליים — אפס כפילויות בתוך עמוד; סמנים עוקבים מ-א' בכל עמוד (הוכח מהייחוס: כל אזורי ההערות של המקור פותחים ב-א'); כל הערה היא הערת [..] אמיתית וכל הערת מקור מופיעה |
| C11 | PDF תקין — מספר עמודים תואם למודל, כל הגופנים מוטמעים |
| C12 | ייצוא HTML (S4.11) — מספר עמודים תואם למודל; כותרת עליונה לכל עמוד תוכן; rtl; אין NaN/undefined — אותו dom-renderer כמו התצוגה החיה |

C4 אינו נכלל בציון שערי האינווריאנטים אלא אם הועבר סף מפורש ומאושר.

הדטרמיניזם נבדק בנפרד: `run-ours.js --determinism` מריץ את העימוד פעמיים
ונכשל אם ה-hash או מספר העמודים שונים.

```bash

python3 tools/layout-parity/verify-corpus.py audits/very_long_test_text.txt \
  audits/very-long-artifacts/ours-model.json audits/very-long-artifacts/ours.pdf \
  audits/very-long-artifacts/corpus-report.json audits/very-long-artifacts/ours.html
```

### מה הקורפוס הגדול חשף (ותוקן — S4.10)
1. **כפילות הערות בתוך עמוד** — שלושה מסלולי דחיפה לתור ההערות, שניים מהם בלי
   דה-דופ: הערה של פסקה שנפתחה ומוקמה באותו עמוד הופיעה פעמיים (70 עמודים
   ב-very_long). אוחדו ל-enqueueNote אחד עם מספור עמודי עוקב מ-א'.
2. **מיזוג הערות סמוכות** — הדבקת '\s+[' יצרה מילה כמו 'אותו[n1][n2]', והחילוץ
   לקח מ-[ הראשון עד-] האחרון: שתי הערות התמזגו לאחת ענקית (1,288 מילים).
   כעת findNotes מפצל את כל ההערות שבמילה (כמו findDelimiterMatches במקור).
3. **בליעת הערה לתוך הערת-צד + דריסה** — ההדבקה חצתה שורות גם לתוך כותרות:
   הערה שבאה אחרי 'כותרת 7' נבלעה להערת-הצד, והערת-צד נוספת שאחריה דרסה
   אותה סופית — 3 הערות וכותרות-צד אבדו לחלוטין (1,353 מילים). כעת ההדבקה
   פועלת לפסקה הקודמת בלבד, והערות-צד מצטברות במקום להידרס.

כל שלושת התיקונים הוכחו כנכונים גם על הייחוס: הציון נשמר (72.2%) וכל
389 הבדיקות ירוקות.
