## הרצה ושחזור

```
# כלי הדפדפן אינם תלויות של ה-repo: npm i puppeteer-core @sparticuz/chromium בתיקייה חיצונית (או CHROME_PATH לדפדפן קיים); נדרש openssl
PERF_BROWSER_MODULES=<node_modules> node tools/perf/browser-boot.js --profile broadband \
    --variants "cold,cold+prefetchlate,cold+prefetchlatefc,warm,reval" --repeat 3 --out out.json
# השוואת לפני/אחרי על עץ חלופי:  --ui-root <עותק של red-build/ui>
```

פרופילים: `local` (ללא הגבלה) · `broadband` (RTT 50ms, 20Mbps משותף) · `slow` (RTT 150ms, 5Mbps משותף). וריאנטים: `cold` · `warm` (טעינה שנייה, מטמון טרי) · `reval` (טעינה שנייה, המטמון פג: בקשות מותנות 304) · `+prefetch` / `+prefetchlate` / `+prefetchlatefc` (שליפה מקבילית של גופני העלייה בתחילת המסמך / אחרי טעינת ה-bundle / כנ"ל עם `cache:'force-cache'`) · `+prefetchlink` / `+preloadlink` (תגיות `<link>`) · `+designsfast` (אוספי העיצוב נשלחים מיד — חסם עליון) · `+fontsimmutable` (גופנים עם מטמון ארוך — חסם עליון ל-force-cache/IndexedDB).

## 1. מתודולוגיה והגבלות

- **שרת מדמה:** HTTP/2 מקומי, gzip לטקסט בלבד (גופנים ללא דחיסה — שמרני), `ETag` + `Cache-Control: public, max-age=600` (כמו GitHub Pages), RTT לכל בקשה (ו-2×RTT לראשונה: TCP+TLS) ורוחב פס משותף בחלוקה שווה. זו הדמיה — לא מדידת Pages.
- **מדדים:** *גופנים מוכנים* = הרגע שבו `document.fonts.size` מגיע ל-11 (כל גופני העלייה נטענו ונרשמו; כיול עצמי בריצה מקומית); *מוכן לעימוד\** = max(סיום ה-bundles כולל ה-Worker, גופנים מוכנים); FCP; `load`; מספר בקשות שהגיעו לשרת. חציון של 3 ריצות (2 בפרופיל `slow`, 5 ב-`local`), הקשר דפדפן נקי לכל ריצה.
- **הגבלות:** vCPU יחיד (מדדים תלויי-CPU מנופחים לעומת מחשב רגיל; מדדי הרשת מעבירים טוב יותר); ריצות שונות נותנות סטיית ±100ms (ב-`slow` ±300ms) — הבדלים קטנים מכך הם רעש; מטמון ה-HTTP נבדק בהקשר אחד בלבד; Chromium יחיד.
- **שיטה שתוקנה בדרך (לשקיפות):** תעודת self-signed עם `--ignore-certificate-errors` מונעת מ-Chrome לשמור תגובות במטמון HTTP — תוצאות מסוג זה נפסלו; המדידות כאן באמצעות `--ignore-certificate-errors-spki-list` (התעודה נחשבת תקינה והמטמון פועל; אומת: `warm` = 0 בקשות לשרת).

קריאה:
- **שליפה מקבילית בתחילת המסמך** (`cold+prefetch`) מקדימה את הגופנים (-31%) אך **מאחרת את FCP/load** (452 → 848ms): 0.9MB גופנים מתחרים ב-bundle על רוחב הפס. תגיות `<link rel=prefetch|preload>` ב-`index.html` נכשלות באותה צורה (FCP 844ms מול 432).

**עלות בתרחישים שאינם היעד [ריצה]:** בטעינה חוזרת (`warm`/`reval`) ובשרת מקומי נמדדו +3% עד +7% (≈ 36–59ms ב-vCPU יחיד) — בגבול הרעש, אך כל ארבעת המקרים חיוביים, ולכן ייתכן שהעלות אמיתית (בקשת הסקריפט + 12 שליפות מהמטמון). זהו המחיר מול רווח של 44%–45% בטעינה ראשונה מארוח מרוחק.

**Parity [ריצה]:** בכל הריצות (לפני ואחרי, שלושת הפרופילים) אין שגיאות דף ומספר ה-FontFace זהה (11). בבדיקה אוטומטית (`tests/unit/font-prefetch.test.js`) רצף `registerFont` (שמות, סדר, sha1 של הבתים) ו-URL-י הגופנים שהספרייה שולפת זהים עם ובלי שליפה — לכן גם ה-layout hash זהה. לא שונו מנוע, parser, מדידה, `app.bundle.js` או קוד UI.

## 3. הכרעה (סוכן 3, לפי תוכנית ההפעלה §4)

1. **צוואר בקבוק מוכח:** ברצף הסדרתי של 12 הגופנים בטעינה קרה מארוח מרוחק — תוספת של ≈ 1.1s (broadband) עד ≈ 3.4s (slow) עד שאפשר לעמוד. זה **אינו** צוואר בקבוק CPU (ראו PERFORMANCE_BASELINE.md) ואינו קיים בשרת מקומי.
2. **אופטימיזציה אחת, מימוש ב-PR נפרד:** שליפה מקבילית מאוחרת של 12 הגופנים (`ui/font-prefetch.js`, `cache:'force-cache'`, מדלג על loopback ו-Data Saver). גופנים מוכנים: broadband -44%, slow -45%; FCP/load ללא שינוי.
3. **לא מוצדקים, ואינם מוצעים:** FontLoader · IndexedDB · `core-fonts.json`/`extended-fonts.json`. מטמון ה-HTTP מכסה טעינה חוזרת (broadband -68% בתוך `max-age`, -37% אחרי פקיעה); התוספת האפשרית ממטמון קבוע היא רק בטעינה חוזרת אחרי פקיעה (חסם עליון -18%), וניתן להשיגה בלי IndexedDB (`force-cache` + URL מגורסן). לא מומש — "הצעה אחת בכל פעם".
