## הרצה ושחזור

```
node tools/perf/font-perf-baseline.js all --repeat 3 --out-dir docs/perf \
     [--woff2-sample <קובץ .woff2>] [--woff2-sizes <json>]
```

הפלט: `docs/perf/baseline-<commit>.json` (נתוני גלם, כולל hash פריסה לכל תצורה). בשכפול מלא גדלי ה-WOFF2 נקראים מהדיסק; בשכפול דליל (כמו בסביבת המדידה) נלקחו מ-`Content-Length` של `raw.githubusercontent.com` (`--woff2-sizes`). מצבי הריצה: `table` — ברירות מחדל של המנוע ללא גופנים רשומים (כמו בדיקות הקורפוס); `app` — ברירות המקור המיובאות + גופני העלייה רשומים כמו באפליקציה (ללא נכסי SVG של שערים/עיטורים). `app` ו-`table` מפיקים פריסות שונות (פרופיל שונה) — השוואת זמנים ביניהם אינה מדידת "עלות גופן אמיתי".

## 1. תמצית

1. **אין צוואר בקבוק CPU בנתיב הגופנים [ריצה].** `parseFont` לכל 444 קבצי ה-TTF ≈ 65–90 ms בסך הכול (חציון < 0.1 ms, מקסימום ≈ 6–10 ms; שתי ריצות); רישום 13 גופני העלייה ב-Worker ≈ 3–9 ms; המרת base64 של גופני העלייה ≈ 12–15 ms. הגופן הכבד ביותר (`Rubik-Pixels-Regular.ttf`, 5 MB) — המרה ≈ 65–75 ms, ורק אם נבחר.
2. **בעלייה הגופנים הם ≈ 9% מהבתים [ריצה: גדלי קבצים; קוד: מה נטען].** 25 בקשות, 10.5 MB לא דחוסים: **אוספי עיצוב 70% (6 קבצי JSON, 7.4 MB)**, חבילות JS 19% (2.0 MB), גופנים 8.8% (12 קבצים, 0.92 MB), קטלוגים 1.9%. `transferSize`, דחיסה וזמני רשת לא נמדדו.
3. **הטעינה כבר עצלה [קוד].** בעלייה נטענים שני קטלוגי JSON (200 KB) ו-12 גופנים; כל משפחה אחרת נטענת בבחירתה בלבד (`app-shell.js:367–374`), עם dedupe בזיכרון (`appliedFontsReady`, `imud-library.js`). ההנחה בתוכנית הישנה ("כל 1,754 הגופנים נטענים בעלייה, 10+ שניות") **אינה נכונה ל-RED**.
4. **FontLoader / IndexedDB / core-extended — אינם מוצדקים לפי הראיות הנוכחיות (DEFERRED).** נשאר מדד אחד פתוח: רצף 12 בקשות הגופנים בדפדפן (מאחורי שני הקטלוגים). אם יימדד שם צוואר בקבוק, ההצעה הראשונה תהיה שליפה מקבילית של בתים **בלי** לשנות את סדר הרישום (אותו hash פריסה), ולא מנגנון cache חדש.
5. **ממצא נכונות בנתיב הגופנים — דורש הכרעה, לא תיקון עצמאי.** 1,289 מתוך 1,721 המשפחות לבחירה (75%) הן WOFF2 בלבד. **[ריצה]** `parseFont(WOFF2)` נכשל (`bad-sfnt-version:0x774f4632`); `exportPdf` עם WOFF2 נכשל (`font:bad-sfnt-version…`) ועם TTF עובד (בקרת חיוב); משפחה לא רשומה נמדדת ב-`table`. **[קוד]** ב-`browser-entry.js` (`getExportFont`, שורות 108–122) משפחה כזו מחזירה את בתי ה-WOFF2 ואינה נופלת לגופן הייצוא היציב. משמעות: לכל גופן מורחב — מדידה שאינה לפי הגופן שמוצג, וייצוא PDF שנכשל (מהתנהגות בדפדפן לא נבדק; הנתיב נבדק ברמת `exportPdf`). הערת קוד ב-`export-api.js` מתעדת סטיית עימוד 2–17% בין `table` למדידה אמיתית — לא נמדד כאן.
6. **אי-עקביות נתונים בהערות הקוד [ריצה].** "98MB" ל-WOFF2 — נמדד 114.8 MB; "443 משפחות" ו-"1,315 משפחות" — בפועל TTF: 451 רשומות / 432 משפחות / 443 קבצים; מורחב: 1,315 רשומות / 1,289 משפחות. 19 משפחות TTF ו-26 משפחות WOFF2 מופיעות פעמיים עם קבצים **שונים בבתים** (ב-TTF נבחר האחרון, ב-WOFF2 הראשון [קוד: `imud-library.js loadFontCatalog`]). לא תוקן — זו החלטת תוכן בקטלוג.
7. **מנוע (להקשר; בעלות סוכן 2) [ריצה].** מסמך 3.3 MB / 704 עמודים ≈ 1.8–2.1 s במצב `app`; 62% מהזמן ב-`legacy-imud-flow.js`, 16% ב-`measure-api.js`, `font-metrics.js` ≈ 1%. דטרמיניזם 3/3 ושימור תוכן בכל 14 התצורות. אין ממצא ביצועי מנוע.

## 5. מה לא נמדד, ואיך משלימים

**לא נמדד** (אין דפדפן בסביבת הסוכן): זמן טעינת האפליקציה; הורדת נכסים (`transferSize`, דחיסה, זמני רשת, מטמון HTTP); פענוח `FontFace`; עומס thread ראשי (פרסור ה-JSON של האוספים, base64, בניית אפשרויות הבורר); זיכרון ה-Worker בדפדפן. הנתונים בסעיף 4 הם בתים וזמני CPU ב-Node/V8 — לא זמני עלייה בדפדפן.

**השלמה ידנית בדקה אחת** (קונסול הדפדפן אחרי טעינה מלאה; קרה: DevTools ← Network ← Disable cache + רענון קשיח; חמה: רענון רגיל):

```js
const e = performance.getEntriesByType('resource');
console.table(e.map(r => ({ file: decodeURIComponent(r.name.split('/').slice(-2).join('/')), KB: Math.round(r.transferSize / 1024), ms: Math.round(r.duration), start: Math.round(r.startTime) })).sort((a, b) => b.KB - a.KB).slice(0, 30));
console.log('בקשות', e.length, '· סה"כ KB', Math.round(e.reduce((s, r) => s + r.transferSize, 0) / 1024), '· סיום אחרון (ms)', Math.round(Math.max(...e.map(r => r.responseEnd))));
```

## 6. הצעות, שערים והכרעות

**אין כרגע הצעת אופטימיזציה לביצוע.** לפי תנאי הקבלה של סוכן 3 — כשלא נמצא צוואר בקבוק אין יוצרים תשתית: לא נוצרו `font-loader.js`, `core-fonts.json`, `extended-fonts.json` או מטמון IndexedDB.

**הצעה מותנית (אחת):** שליפה מקבילית של בתי גופני העלייה בלבד, עם **אותו סדר רישום ב-Worker**, כך שה-hash פריסה זהה. תנאי: מדידת דפדפן שמראה שהרצף הסדרתי תורם חלק מהותי מזמן העלייה. עלות: שינוי ב-`src/ui/` (בבעלות סוכן 1) — נדרש תיאום.

**שער לכל PR אופטימיזציה עתידי (G4/G5):** hash פריסה זהה לבסיס שבסעיף 4 (עמודת `hash`) לאותו קלט ואותו מצב; הצגת לפני/אחרי של בתים, בקשות וזמן; `contentPreserved` נשמר.

**הכרעות ותיאום נדרשים:**
